# Client portal on the adopted local Kubernetes platform

Status: implemented locally on Kind, 5 October 2026. No production or cloud deployment is implied.

Extend the existing Next.js App Router site instead of replacing its approved portfolio design. Add invited Keycloak accounts with a confidential client, server-side OIDC validation using openid-client, and opaque HttpOnly sessions persisted in PostgreSQL. The application validates ID-token signatures explicitly in addition to issuer, audience, expiry, nonce, state and PKCE. Store no tokens in browser storage. Fixed local HTTP is an explicit development setting; cloud configuration requires TLS and updated exact redirect/origin/logout URLs. Owner invitations require OTP enrollment. Real owner selection is not inferred.

Use native SQL migrations instead of an ORM to preserve PostgreSQL exclusion constraints and transaction semantics. A Helm-owned Job applies numbered/checksummed migrations under an advisory lock. Runtime uses the isolated portal database role; PostgreSQL remains in the database namespace. Existing draft SQL is historical, not another active schema initialization path.

Availability is a set of individual 30-minute windows. Clients request rather than reserve. Approval locks the window and confirms at most one request using an exclusion constraint; competing requests are declined transactionally. Requested, active, completed and cancelled engagements have private conversations. Owner/admin access spans engagements; client access is limited to its own rows, and demo-viewer cannot mutate. The public portfolio remains anonymous.

PostgreSQL is authoritative for chat and booking data. Commit each change together with an outbox event. Redpanda transports versioned metadata-only events to the worker, which deduplicates processed event IDs and creates portal notifications. This is at-least-once delivery. Browser message polling reads the authorized database endpoint every three seconds, pauses when hidden and uses sender/nonces to prevent duplicate retry messages. WebSockets and external chat connectors are unnecessary for the initial private portal. Publication failure never loses a successfully saved booking/message. Exhausted publisher retries remain inspectable in the outbox; malformed or unavailable-reference envelopes move to sanitized dead-letter records.

The same worker collects fixed Prometheus workload readiness metrics every 30 seconds and persists an allowlisted snapshot. Public API responses exclude internal labels, addresses and private user data; missing or older-than-two-minute data is unknown/stale. This represents local Kind workload readiness, not functional end-to-end uptime, individual visitor traces, Azure telemetry, or high availability. Rich infrastructure 3D topology and other observability measures remain a future slice.

The local cluster shares Docker Desktop's approximately 8 GiB with editor and build processes. Next page-generation concurrency is capped at two in source, worker-only changes have a small bundled image path, and tests run sequentially. During implementation the Kind scheduler and controller-manager repeatedly lost default ten-second lease renewal deadlines under build load; local static-pod settings were backed up and tuned to a 60-second lease / 40-second renewal deadline / 5-second retry. This Kind-only operating adjustment is reversible with `scripts/tune-kind.py --restore`, is outside the application Helm release, and is not a production sizing claim. Cloud releases still require measured resource headroom.
